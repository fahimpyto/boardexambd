# BoardExamBD

BoardExamBD is a static guide site for SSC, HSC and university admission notices in Bangladesh. It covers exam routines, results, form fill-up, board challenge, practical exams and admission dates for DU, BUET, medical, GST, RU, RUET, KU and SUST.

The public site has **21 indexable pages**: the home page, three category hubs, a blog hub and 16 guides. `404.html` is a tracked but `noindex` utility page and is excluded from the sitemap and progress totals.

## Stack

- Static HTML generated by Python scripts.
- Tailwind CSS 3.4.17 compiled to `assets/css/tailwind.css`. The Play CDN is not used.
- No analytics scripts are loaded until real GA4 and verification IDs are available.
- Shared Open Graph image at `assets/images/og-default.jpg` until per-page images are designed.

## Build locally

Requirements:

- Python 3.11 or newer with `beautifulsoup4`, `markdownify`, `openpyxl` and `Pillow`.
- Node.js and npm.

Install dependencies and build:

```powershell
python -m pip install -r requirements.txt
npm install
python tools/build_site.py
npm run build:css
python tools/validate_site.py
python tools/stage_site.py
```

`npm run build` runs the site generator, CSS build and deployment staging together. Run `validate_site.py` afterwards.

**Build order matters.** Generate the HTML first, then compile Tailwind, because Tailwind scans the generated `*.html` files for class names. Re-run the CSS build after any HTML or template change. The staging step must run last so `dist/` receives the final CSS and HTML.

Serve the source site locally with the same extensionless URLs as production:

```powershell
npm run serve
```

Then open <http://127.0.0.1:8080/>. To preview the exact deployment bundle, run `npm run serve:dist` and open <http://127.0.0.1:8080/>.

## Editing content

Most page-level changes belong in `tools/seo_config.py`: titles, descriptions, keywords, publication and review dates, FAQs, checklists, official sources and related guides. Rebuild after changing it.

Article bodies are preserved inside `<!-- svc:body:start -->` and `<!-- svc:body:end -->` markers in each article file. Key facts use their own markers. The build reads those blocks back on every run, so rebuilding is idempotent and does not rewrite the facts in the original guides.

Dates use date-only values in `YYYY-MM-DD` form. Do not invent publication times or add unverified claims.

## SEO implementation

Every indexable page has:

- A unique title and meta description within the configured length limits.
- A canonical URL and `hreflang` alternates.
- Explicit robots directives.
- Open Graph and Twitter Card tags with the shared image.
- One H1 and a valid heading hierarchy.
- JSON-LD for `Organization`, `WebSite` and the page type, plus `Article`, `BreadcrumbList` and `FAQPage` where relevant.
- A visible breadcrumb except on the home page.

Articles also include a hero, meta row, table of contents, key facts, quick checklist, 3–5 FAQs, official sources, author box and related guides. Each article has a Markdown alternate at `/md/<slug>.md` and a `<link rel="alternate" type="text/markdown">` reference.

Generated crawler files:

- `sitemap.xml`: all 21 indexable URLs.
- `robots.txt`: allows search and AI crawlers, disallows `/404` and `/SEO_TEMPLATE`.
- `llms.txt`: site summary, core pages, every guide and its Markdown mirror.

## QA

Run the local validator after every build:

```powershell
python tools/validate_site.py
```

It checks all 22 generated pages and the generated assets for metadata, robots, canonicals, Open Graph, Twitter Cards, structured data, H1 counts, internal links, duplicate IDs, heading jumps, article furniture, FAQ counts, sitemap coverage, favicon sizes, the compiled stylesheet, robots, `llms.txt`, Markdown files and duplicate metadata.

The validator must pass before a tracker row is marked Done.

## Tracker

`SEO_Tracker.xlsx` contains:

- **Dashboard**: progress, coverage by check, progress by cluster and a reminder.
- **Pages**: one row per generated page, with metadata checks, QA status and review dates.
- **Issues**: open deploy/content items and completed fixes.
- **Config**: canonical domain, author, OG image, integrations and build notes.

`404.html` appears in `Pages` for completeness, but its `Utility` type is excluded from the dashboard's progress and coverage totals. It is also excluded from the sitemap and marked `noindex`.

**Warning:** running `python tools/make_tracker.py` recreates the workbook and resets every page status to “Not started.” Only run it when you intend to rebuild the tracker, then mark each verified page Done again.

## Deployment

The site is deployed with Cloudflare Workers static assets. Only `dist/` is published; the repository root is never used as the asset directory.

`python tools/stage_site.py` rebuilds `dist/` from the generated HTML, `assets/`, `md/`, `ssc-26-routine/`, `sitemap.xml`, `robots.txt` and `llms.txt`. It rejects files over Cloudflare's 25 MiB limit and bundles over 20,000 files.

Cloudflare build settings:

- **Build command:** `npm run build`
- **Deploy command:** `npx wrangler deploy`
- **Build output directory:** `dist`
- **Root directory:** leave empty

`wrangler.jsonc` sets `assets.directory` to `./dist` and enables Cloudflare's `drop-trailing-slash` HTML handling, so `/blog` serves `blog.html` and missing pages return `404.html`. `worker.js` runs first for `.html` and trailing-slash requests and permanently redirects them to the extensionless URL. Canonical URLs, sitemap entries and internal links are all extensionless.

`.assetsignore` is a fallback that prevents dependencies, tooling and source PDFs from being uploaded if the project is ever pointed at the repository root.

Configure the host to:

- Serve the canonical origin `https://boardexambd.com`.
- Use `404.html` as the custom not-found page.
- Preserve HTTPS and serve `/sitemap.xml` and `/robots.txt` at the domain root.

Do not commit `dist/`; it is generated from the committed HTML and assets. Live validation is still pending until `boardexambd.com` resolves and the site is deployed.
